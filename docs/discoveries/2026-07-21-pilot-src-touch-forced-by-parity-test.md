# Discoveries — pilot pattern vs. src/ parity test, and where "canonical" actually lives

**Date:** 2026-07-21
**Spec:** `docs/features/2026-07-21-living-harness/specs/build-ledger-lifecycle.md`

## PILOT "never touch src/" collides with `session-end-rescope.test.ts`
**Expected:** Editing only `.claude/skills/joycraft-session-end/SKILL.md` (like spec 1 did for `joycraft-add-fact`, which has no such test) would satisfy the pilot pattern.
**Actual:** `tests/session-end-rescope.test.ts` asserts byte-for-byte equality between `.claude/skills/joycraft-session-end/SKILL.md` and `src/claude-skills/joycraft-session-end.md`, so editing only the installed copy broke it.
**Impact:** Future PILOT specs touching a skill should check for a `*-rescope.test.ts`/sync test before assuming "installed copy only" is safe.

## `src/claude-skills/*.md` is itself a generated artifact, not the true canonical
**Expected:** Editing `src/claude-skills/joycraft-session-end.md` directly (the file `session-end-rescope.test.ts` compares against) would be a durable fix.
**Actual:** `src/claude-skills/`, `src/codex-skills/`, and `src/pi-skills/` are all generated by `scripts/generate-bundled-files.mjs` from the true canonical source `src/skills/joycraft-session-end.md`. Any rebuild (e.g. `pnpm build`, or another agent's session-end/spec-done flow invoking the generator) silently discarded the direct edit. The durable fix had to go in `src/skills/`, scoped to Claude only via `<!-- harness:claude -->...<!-- /harness -->`, then regenerated with `node scripts/generate-bundled-files.mjs` and copied into the three installed-copy dirs (`.claude/skills/`, `.agents/skills/`, `.pi/skills/`).
**Impact:** For any single-source skill (i.e. one present in `src/skills/`), PILOT edits belong in `src/skills/<name>.md` with a harness-scoped block, not in a derived `src/*-skills/` file — editing the derived file is a silent no-op the moment anyone regenerates. `joycraft-add-fact` happened not to trip this in spec 1 only because nothing regenerated the bundle in that window, not because it was safe.

## Confirmed repo-wide by the taxonomy sweep (upgrade-optimize-v2)
**Expected:** The taxonomy sweep's "MUST NOT touch `src/`" constraint would hold for all 22 skills.
**Actual:** Four skills carry byte-parity tests against `src/claude-skills/` (`decompose-modes.test.ts`, `implement-mode-handoff.test.ts`, `spec-done-skill.test.ts`, `session-end-rescope.test.ts`); for those, the sweep had to follow the canonical-source path above (edit `src/skills/<name>.md` with a `<!-- harness:claude -->` block, regenerate, sync). The other 18 skills (no parity test) were safely edited installed-copy-only.
**Impact:** "MUST NOT touch src/" in PILOT specs needs a standing exception for any skill with a parity test — check for one before assuming an installed-copy-only edit is safe.
