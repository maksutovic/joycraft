# Polish the runtime from the independent reviews' follow-ups

Parent: [brief](../brief.md). Source: [review follow-ups](../review-followups.md), the items marked **fix** that change a runtime file other than `archive.mjs` and `dispatch-start.mjs` (those are spec 29, because they are under review now). All 13 decisions are answered; they are quoted by ID.

Each bullet fixes one follow-up group in one file area. The spec in brackets is the spec whose code the bullet repairs.

## acceptance

- Gate matching in prose [specs 4, 8]: `namesCommand` in `queue-check.mjs` also matches the recorded command in plain text (outside a code span) when a plain word (letters only) or a dash (`—`, `–`, or ` - `) follows it, and it matches a fenced code line inside a bullet that holds only the command. A code span still matches only when it ends at the command, and an argument (a word with `/`, `.`, `-` or `=`) still makes a different command. `cleanup.mjs` gate-rule uses the same function, so it gets the same rule. **Open-input rule:** the check set is the cases in `tests/runtime-queue-check-gate.test.ts`; a missed gate costs more than a false gap (Max's core case); the threshold is 0 misses and 0 matches on the argument forms. Check: `tests/runtime-queue-check-gate.test.ts` with gate `pnpm verify` gives one `gate-in-spec` gap each for "Check: run pnpm verify before merging.", "Check: pnpm verify — then read the log." and a bullet whose fenced line is `pnpm verify`, and none for `` `pnpm test tests/x.test.ts` ``, "pnpm test tests/x.test.ts" and "pnpm test -- --run" with gate `pnpm test`; `tests/runtime-cleanup-gate-rule.test.ts` gives one gate-rule finding for the AGENTS.md line "- Run pnpm verify before merging.".
- Gate gap next step [spec 4]: a `gate-in-spec` gap ends with "Use the spec's own test command instead." and does not say "ask the user"; every other gap kind keeps today's next step (`queue-check.mjs:14`). Check: `tests/runtime-queue-check-gate.test.ts` finds that sentence at the end of the gate gap and finds "ask the user now" at the end of a `missing-check` gap.
- Report gate wrappers [spec 6]: `refuseGateRuns` in `completion.mjs` finds the gate inside `bash -lc <gate>`, `sh -c <gate> sh` (more arguments after the command), `zsh -c`, `dash -c`, `/usr/bin/env bash -c <gate>` and a leading `env NAME=value ...` (`env CI=1 pnpm verify`). A `joycraft.yaml` that does not parse refuses `check-report` and `finalize-review` with exit 2 and names `joycraft.yaml`; it never passes (`completion.mjs:129`). Check: `tests/runtime-report-gate.test.ts` with gate `pnpm verify`: each of the six argv forms exits 2 naming `tests.gate`; argv `pnpm verify tests/x` passes; a `joycraft.yaml` of `tests: [` exits 2 with `joycraft.yaml` in stderr.
- Gate-rule record helper [spec 16]: `node .joycraft/runtime/cleanup.mjs gate-rule --record rewritten` (or `kept`) writes `cleanup.gateRule` into `.joycraft/preferences.json`, keeps the other keys, and creates the file with `schemaVersion: 1` when it is absent; `gate-rule --check` prints `rewritten`, `kept` or `unset`. It refuses another value and a symlinked `.joycraft` or `preferences.json` with exit 1 and changes nothing, as `archive.mjs ignore --decline` does. Check: `tests/runtime-cleanup-gate-rule.test.ts`: `--record kept` on `{"schemaVersion":1,"artifacts":{"pages":"local"}}` gives `{"schemaVersion":1,"artifacts":{"pages":"local"},"cleanup":{"gateRule":"kept"}}` and `--check` then prints `kept`; `--record maybe` and a symlinked `preferences.json` exit 1 and leave the bytes as they were.
- Receipt tail [specs 3, 7]: `readFooter` in `evidence.mjs` returns a footer whose line is longer than 64 KiB, and the failing `tail` (and the trailing-newline check) starts at a line start: when the read window starts inside a line, that partial line is dropped, and no UTF-8 character is split (`evidence.mjs:222`). Check: `tests/runtime-evidence-receipt.test.ts`: a command with one 70,000-character argument gives a receipt whose `readFooter` result holds that argv; a failing command that prints one 300 KiB line, then `a` and `b`, gives `tail` `a\nb`.
- Signals before the fault [spec 9]: `runEvidence` installs its SIGINT, SIGTERM and SIGHUP handlers before `git apply` of the patch, not after the spawn, and a stop that comes before the child exists restores the patch and removes nothing else (`evidence.mjs:316-334`). Check: `tests/runtime-evidence-patch.test.ts`: with a `git` wrapper first on `PATH` that sleeps 1 s before it runs `git apply -- <patch>` (and passes `--check`, `--numstat` and `-R` straight through), a SIGTERM sent to `evidence.mjs run --patch` during that sleep ends it with exit 143, and `git diff --quiet` then exits 0.
- Restore covers the whole tree [spec 9]: after the reverse apply, `restored` is true only when the file hashes match and `git status --porcelain` (the new receipt left out), `HEAD` and `refs/stash` are as they were before the run (`evidence.mjs:260`). Check: `tests/runtime-evidence-patch.test.ts`: a command that appends to another tracked file, one that runs `git commit --allow-empty -m x`, and one that runs `git stash` each give `restored: false` and exit 1; the plain fault run still gives `restored: true`.
- Project in a repository subfolder [spec 9]: `preparePatch` reads `git rev-parse --show-prefix`, resolves the patch's paths against it for the hashes, and refuses with exit 2 a patch that touches a path outside the prefix, before anything is applied (`evidence.mjs:253`). Check: `tests/runtime-evidence-patch.test.ts`: in a repository whose project is `app/`, a fault made with `git diff` on `app/add.mjs` and run from `app/` makes the check fail and gives `restored: true`; a patch that touches `lib/other.mjs` exits 2 and `git status --porcelain` stays empty.
- Environment map checks [spec 12]: `readEnvMap` refuses with exit 2 an empty name, a name with `=`, and a NUL in a name or a value, and each message names `.joycraft/local/evidence-env.json`; a map name that equals `CI` or `JOYCRAFT_EVIDENCE` in any letter case is never applied or listed; an untracked map that Git does not ignore (`git check-ignore`) is refused with exit 2 ("must be git-ignored"). Check: `tests/runtime-evidence-env.test.ts`: maps `{"": "1"}`, `{"A=B": "1"}` and `{"A": "x\u0000y"}` each exit 2 with the map path in stderr; `{"ci": "0", "W": "3"}` gives `env: ["W"]`; a map in a fixture whose `.gitignore` does not list `.joycraft/local/` exits 2, and the same map runs once the folder is ignored.
- Status load line [specs 10, 19]: the line says why in a few words, names each distinct core count, and drops the core count when no footer has one. Check: `tests/runtime-status-load.test.ts`: the 14-core fixture prints exactly "2 of 3 test runs started above the core count (14 cores). An overloaded machine makes slow, flaky runs that agents rerun. Cap workers per run with the runner's own flag; see setup."; footers with 8 and 16 cores print "(8 and 16 cores)"; footers without `cores` print no "(0 cores)" and no parenthesis.
- Test-changes base and declarations [spec 17]: `test-changes.mjs` refuses with exit 1 a base that is not an ancestor of `HEAD` (`git merge-base --is-ancestor`), and it lists under `rewritten` each base declaration whose requiring text the current spec changed (same path and class, other words). Check: `tests/runtime-test-changes.test.ts`: a base on a side branch exits 1 with "not an ancestor of HEAD"; a spec whose class-1 bullet's requiring text is edited after the base lists that path under `rewritten`.
- Test-changes file rules [spec 11]: a declaration of either path of a Git rename covers both (`git diff -M` pairs them; `test-changes.mjs:123`); the `*Test`/`*Spec` file-name rule and the camelCase `*Test` folder rule count only inside a known test source set (`test`, `tests`, `androidTest`, `androidUnitTest`, `androidInstrumentedTest`, `commonTest`, `jvmTest`, `jsTest`, `iosTest`, `nativeTest`, `integrationTest`); a deleted path counts as a test only when its base object is a blob. **Open-input rule:** the check set is the `tests` and `others` lists in `tests/runtime-test-changes.test.ts`; a missed test costs more than a listed look-alike; the threshold is 0 errors on that set. Check: `tests/runtime-test-changes.test.ts`: a declaration of only `tests/renamed.test.ts` puts `tests/old.test.ts` and `tests/renamed.test.ts` in `declared`; `abTest/x.ts`, `src/main/ProductSpec.kt`, `src/main/LoadTest.java`, `lib/FooTest.java` and `src/main/BarTest.kt` are not tests; `src/test/java/FooTest.java`, `app/src/jvmTest/kotlin/BarSpec.kt` and `app/src/androidTest/java/Foo.kt` are; a removed submodule at `tests/vendor-lib` is in `skipped` and not in `testFiles`.
- Plain gate and shell path [spec 7]: in `delivery.mjs`, a plain-word gate in shell form matches only when the line splits on spaces and tabs alone (a newline or carriage return refuses), and a shell path is refused when it is inside the project or, on POSIX, in Windows form (`delivery.mjs:113`, `:125`). The usage text states the symlinked-shell limit beside the forged-footer limit. Check: `tests/runtime-wave-gate.test.ts` with gate `node gate.mjs`: footers with argv `["sh","-c","node\ngate.mjs"]`, `["<root>/tools/sh","-c","node gate.mjs"]` and (POSIX) `["C:\\Program Files\\Git\\bin\\bash.exe","-c","node gate.mjs"]` each give `gate-receipt-not-gate`; `["sh","-c","node  gate.mjs"]` and `["/bin/sh","-c","node gate.mjs"]` push; the usage text contains "symlink".
- Receipt after records commits [spec 7, spec 15 review]: `checkGateReceipt` accepts a green, clean receipt whose revision is an ancestor of `HEAD` when every path changed since that revision (`git diff --name-only --no-renames <revision> HEAD`) is under the docs root (the common parent of `paths.features`, `paths.archive` and `paths.context`, as `cleanup.mjs` `docsRoot` computes it); a docs root of `.` gives no exemption, and any other changed path, such as a test an archive `--rewrite` edits, keeps `gate-receipt-stale`. Check: `tests/runtime-wave-gate.test.ts`: a green receipt at the first commit, then a commit that changes only `docs/features/f/notes.md`, pushes and reports that revision; a later commit that changes `tests/a.test.ts` gives `gate-receipt-stale`; a receipt on a revision that is not an ancestor of `HEAD` gives `gate-receipt-stale`.

- Checks seam line forms [drift-tidy]: tidy also reads `path:line rule message` (markdownlint-cli2) when the path ends in a file extension with a letter, and an absolute path inside the project becomes project-relative; `settings.md`'s `checks:` row tells users to pick the checker's line output format.
