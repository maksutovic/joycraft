D1 · ROUTING ENCODING

How do skills carry the routing?

Skills are prompts — they can't force the main-loop model, only recommend it. What they CAN enforce is the model on every subagent they spawn. The question is where the routing lives.

Inline: preamble + subagent params

Recommended
  • Skills stay self-contained (gotcha #3) — nothing new to install or upgrade
  • ≤3-line preamble per skill; model params on spawns are already supported
  • Tier intent named alongside model ID — one-line swap when models change
  • Routing not user-configurable without editing skills
  • Recommendation text duplicated across skills (mitigate: identical snippet, one canonical form)
Blast radius
~9 skill files x 2 harnessesbundle regen + sync

Shipped .claude/agents/ definitions

  • Model set in agent frontmatter — visible, user-editable config
  • Named agents (joycraft-implementer) reusable outside joycraft flows
  • A whole new install/upgrade surface (init, upgrade, state tracking)
  • Claude-only concept — codex path diverges structurally
  • Agent-frontmatter model behavior across CC versions unverified

  • Config flexibility + inline defaults
  • Two routing sources that can disagree — a new two-systems drift, freshly warned against (RF-4)

D2 · VERIFIER TIER

What model runs joycraft-verify?

The reading-fatigue panel made the verifier the independent sensor that earns not-reading (RF-KILL-3): silence is only trustworthy if the thing emitting it is strong. This is a trust decision wearing a cost decision's clothes.

Inherit (orchestrator tier, Opus)

Recommended
  • Verifier ≥ implementer in capability — Sonnet's work checked by a stronger model
  • No extra config; runs at whatever tier the driver runs
  • Matches Anthropic guidance: frontier for verification, workers for execution
  • Verification costs orchestrator-tier tokens on every spec
Blast radius
verify spawn: no model param

Sonnet (same as implementer)

  • Cheapest; verification scales freely
  • Peer-grading: same-tier model checking same-tier work weakens the independence the panel demanded
  • The dark-tier trust story ("silence is earned") rests on this sensor
Blast radius
verify spawn: model sonnetweaker sensor

Explicit Fable

  • Strongest possible sensor
  • Frontier tokens on every spec of every feature — the cost profile Anthropic's pattern exists to avoid
  • Unavailable on plans without Fable (couples to D3)
Blast radius
verify spawn: model fableplan-gated
D3 · DEGRADATION POLICY

What happens without Fable access?

Not every Joycraft user's plan includes Fable (or Sol). The skills ship to strangers' machines — routing has to fail gracefully or the skills break on day one for a chunk of users.

Recommend-and-degrade, one ladder

Recommended
  • Preamble names the tier ladder (Fable → Opus → session model); skill proceeds on the best available
  • Zero hard failures; works on every plan
  • Tier intent language makes the degradation self-documenting
  • Users on lower tiers silently get weaker planning (mitigate: preamble says so once, out loud)
Blast radius
preamble snippet only

Hard require, fail with message

  • No silent quality degradation ever
  • Skills refuse to run for a chunk of users — hostile for a scaffolding tool
  • Unenforceable anyway: a prompt can't actually block a session
Blast radius
breaks lower plans
Integrity

Assumptions asserted as fact

Load-bearing claims not posed as questions, labeled per RF-5.

Verified

Anthropic's pattern: Fable advises/plans, Sonnet executes — published benchmark 96% of all-Fable performance at 46% cost; Opus positioned for everyday complex load. (Web-verified today, secondary sources citing Anthropic.)

Verified

OpenAI's guidance: Sol for ambiguous/high-value planning, Terra 2x-cheaper scoped implementation — openai.com model pages + handoff guidance, web-verified today.

Verified

Subagent model overrides are enforceable — the Agent tool accepts a model parameter per spawn; used in this session's own workflow (52 agents).

Unverified

The Opus middle tier is Max's adaptation, not Anthropic's benchmarked config. Anthropic's 96%/46% number is Fable-orchestrator + Sonnet-workers, two-tier. No benchmark exists for Fable-plan/Opus-orchestrate/Sonnet-implement. Reasonable, but unmeasured.

Unverified

A skill preamble can reliably detect the running model and prompt a switch. The model self-identifies in its system prompt, but this behavior from an installed skill in a fresh project is untested — same verification spike as the decision-dossier feature's spec 1.

Unverified

.claude/agents/ frontmatter model behavior is consistent across Claude Code versions — matters only if D1 chooses agent definitions.
