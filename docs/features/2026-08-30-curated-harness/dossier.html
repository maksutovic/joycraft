D3 · SCANNER DELIVERY

How does the telemetry scanner ship and run at session-end?

The scanner must parse three JSONL dialects (one of them shell-string guesswork) and aggregate counts. Skills are copied files that work without Joycraft installed, and STE D2 already ruled a user-side script obligation out of the spirit of a skill — every delivery path breaks one norm or another.

CLI subcommand — npx joycraft telemetry

Recommended
  • Real TypeScript with unit tests — the detect.ts idiom the repo already trusts
  • Codex shell-string parsing is far saner in code than in skill prose
  • Session-end skips gracefully when unavailable (evidence: INACCESSIBLE)
  • Soft npx dependency in a skill designed to work without Joycraft installed
  • npx cache staleness is a known trap (0.7.10 session)
Blast radius
src/telemetry.ts (new) src/cli.ts joycraft-session-end.md joycraft-optimize.md npx availability at session-end

Inline bash/jq in the skill

  • Fully self-contained — zero install, matches the copy-not-symlink rule
  • jq is not guaranteed on user machines
  • Untestable aggregation logic in prose — the exact failure mode we call degraded in Codex
  • Bloats a skill already 11 lines over budget
Blast radius
joycraft-session-end.md untested shell logic × 3 harness dialects

Shipped script installed at init

  • No npx dependency; testable in the repo
  • STE D2 precedent: a user-side script obligation is "out of the spirit of a skill"
  • New installed surface to sync, upgrade, and hash-track
Blast radius
new installed tree entry sync-skills.mjs upgrade.ts state hashes contradicts STE D2

D4 · EVIDENCE SURFACE

How does telemetry evidence appear in optimize's report?

The brief sketched new evidence labels (NEVER_READ, WRITE_HEAVY), but optimize's vocabulary rule says "exactly five, no synonyms" and keeps evidence labels disjoint from dispositions. Measured counts are findings, not evidence classes — the two framings pull in opposite directions.

Read/Write column, labels unchanged

Recommended
  • Preserves the exactly-five contract and its tests
  • The ratio column is the brief's own stated success metric
  • VERIFIED applies cleanly when telemetry.json was read this run
  • "Never read" is a cell value, not a greppable one-word label

D5 · DIRECTIONAL CONTENT SHAPE

What shape does product identity / glossary / taste take in generated CLAUDE.md and AGENTS.md?

Neither generator emits directional content today. The merge machinery appends whole sections guarded by header regexes, and the two files do not share that code — every extra section multiplies regex surface in two places. Template content is the core product (ask-first).

One ## Product Identity section

Recommended
  • Single append unit: one generator + one regex per file
  • Values, glossary, and taste read as one directional block
  • A user wanting only a glossary carries the sibling subsection headings
Blast radius
improve-claude-md.ts agents-md.ts gather-context.md (+questions)

Three top-level sections

  • Independently mergeable when a user already has one (e.g. a Glossary)
  • Triples the regex surface in two unshared merge chains
Blast radius
improve-claude-md.ts ×3 agents-md.ts ×3 6 new regex guards

Doc-layer only, behind a Context Map pointer

  • Zero merge-logic risk
  • Directional content is exactly the always-loaded kind — a pointer defeats the values-not-disciplines point
Blast radius
src/templates/context/ (new file) identity content not always loaded
D6 · ARCHITECTURE TREE

What happens to the generated architecture section?

The critique calls the where-code-lives map "probably the least useful thing" and the fastest to drift, but hedges with "keep it to folders… or drop it." The generator currently scaffolds a full tree; existing user files are protected by the header-regex guard either way.

Slim to folders + one-line descriptions

Recommended
  • Implements the trim with zero migration — existing files untouched
  • Adds an agent-maintainable framing note at generation time
  • Existing installs keep their big trees until tune nudges
Blast radius

Drop the section from new installs

  • Nothing left to drift
  • No evidence users don't read it; overshoots the brief's hedge
