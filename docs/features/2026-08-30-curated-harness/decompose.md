## Execution waves

- **Wave 1:** specs 1, 7, 9, 12, 13, 14 — **parallel-safe** (Affected Files disjoint; specs 7 and 14 edit different skill files, so their regenerated trees do not collide).
- **Wave 2:** specs 2, 3, 10, 11 — **NOT parallel-safe** (overlap: specs 2 and 3 both touch the `src/telemetry.ts` entry point). Run sequentially.
- **Wave 3:** specs 4, 5 — **parallel-safe** (session-end vs optimize, disjoint files and tests).
- **Wave 4:** spec 6 — sequential (edits both wave-3 skills plus the lifecycle doc).
- **Wave 5:** spec 8 — sequential (edits add-fact and session-end after specs 6 and 7 settle them).

Feature mapping per the design: feature 1 `earn-your-keep` = specs 1–7 (WS1+WS2), feature 2 = specs 8–11 (WS3+WS4). Spec 12 (WS5) rides any release PR. Specs 13–14 (WS6) ship independently.

## Execution modes

No `**Default execution mode:**` line exists in CLAUDE.md, so the project default is `batch`. The recommendation above follows the size heuristic: spec 1 (L, greenfield parser surface) → `isolated`, M specs → `checkpoint`, S/XS specs → `batch`. The mix is recorded per-spec in frontmatter and the queue manifest — adjust before implementation if wanted.
