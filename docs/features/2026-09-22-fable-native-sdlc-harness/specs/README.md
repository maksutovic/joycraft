## What this feature does

Makes Joycraft's installed harness Fable-5.1-native through one model-profile reference doc that CLAUDE.md points at and skills cite by block name; adds a `docs/intent/` inbox that interview writes into and triages, and that new-feature and bugfix consume; ships the playbook's governance pieces that fit the existing machinery (unregistered hook recipes, an inert evals-in-CI scaffold, and an advisory optimize source that flags pre-Fable rules); then dogfoods the whole install on this repo.

## Execution waves

- Wave 1: specs 1 → 2 → 5 → 9 → 10 — NOT parallel-safe (overlap: `docs/.joycraft/manifest.json`, `tests/bundle-inventory.test.ts`, `tests/model-profile-template.test.ts`, `tests/init-selections.test.ts`). Run in that order.
- Wave 2 (after wave 1): specs 3, 6, 8, 11 — parallel-safe (Affected Files disjoint). Worktrees only: `pnpm sync-skills` rewrites every installed tree, so two syncs in one checkout can capture each other's half-edits.
- Wave 3 (after wave 2): specs 7 → 4 — NOT parallel-safe (overlap: `src/skills/joycraft-interview.md`). Spec 4 runs last so its citations land after specs 6, 7, and 8 restructure the interview and new-feature skills.
- Wave 4 (after wave 3): spec 12 — sequential.

Parallel-safe = the wave's specs touch disjoint Affected Files, so they may run as
concurrent subagents/worktrees. Waves without the marker run sequentially.
`src/bundled-files.ts` is gitignored and regenerated by the test suite, so it is not counted as an overlap.

Mode mix: specs 5 and 8 are `batch`; all others are `checkpoint`. The brief placed spec 4 in wave 2; it moved to wave 3 for the file overlap above.

## Hazards carried from decomposition

- A new file under `src/templates/` reaches this repo's `docs/templates/` only when the built updater runs here (`pnpm build && node dist/cli.js update .`). `pnpm build` alone leaves it out of the manifest. Every template-adding spec (1, 5, 9, 10) lands that copy in its own commit; spec 12 only verifies zero drift.
- Every `src/skills/` edit regenerates variants and runs `pnpm sync-skills` in the same commit (specs 4, 6, 7, 8, 10, 11).
- `src/init-autofix.ts` writes every `workflows/`-prefixed template key into `.github/workflows/`. The evals scaffold must stay under `evals/`, never `workflows/`.
- Skill and template content edits are ASK FIRST boundaries: pause for approval before the first write under `src/skills/` or `src/templates/`.

## How to use this file

Run the whole queue with `/joycraft-implement-feature docs/features/2026-09-22-fable-native-sdlc-harness/` — it executes the specs in wave order (parallel-safe waves may run as concurrent subagents; everything else runs sequentially in the driving conversation) and finishes with session-end. Or run one spec at a time with `/joycraft-implement <spec-path>`; the implement skill reads this README first so it understands the spec's position in the wave plan, and continues through the queue itself. Each spec is self-contained for the actual implementation; this README provides ordering context only.
