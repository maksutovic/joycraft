Joycraft Decision Dossier · feature: human-readable-output-style · July 27, 2026

How should a house output style bind Joycraft's skills?

Locked: no new user-invocable skill, one reference doc cited by path, human-facing moments only, no rubric self-scoring loop. Open: where the doc lives, whether the rules are short-positive or a full banned list, how far a test enforces it — plus two ASK FIRST boundary crossings this feature cannot avoid.

B1 · BOUNDARY · SKILL CONTENT

This feature edits skill bodies, which AGENTS.md lists as ASK FIRST. Proceed?

"Changing skill content — skills are the user-facing interface" is an explicit ASK FIRST boundary. Adding a style pointer to human-facing skills means editing src/skills/*.md, regenerating three harness variants, and syncing installed copies. This question is mandatory and exempt from the question cap — I am not permitted to assume the answer.

Approve scoped skill edits

Recommended
  • The feature is impossible without it — a reference doc no skill cites is a doc no agent reads at the moment it matters
  • docs/reference/skill-authoring.md is the live cautionary precedent: shipped nowhere, cited by no skill
  • Edits are additive one-line pointers, not rewrites of existing steps
  • Touches the user-facing interface across up to 9 skills
  • Every edit needs bundle regen + installed-copy sync in the same commit or parity tests fail
  • Pointer placement risks the position-fragile 1500-char test windows
Blast radius
src/skills/*.md src/{claude,codex,pi}-skills/ src/bundled-files.ts .claude/skills/** (byte-match)

Reference doc only, zero skill edits

  • Does not cross the ASK FIRST boundary at all
  • Smallest possible diff; no regen, no parity risk
  • Reproduces the skill-authoring.md failure mode by design — an uncited doc
  • Nothing carries the style rule to the output moment where it applies
  • Ships the appearance of a contract without the mechanism
Blast radius
one new .md file
B2 · BOUNDARY · TEMPLATE CONTENT

Should the style doc ship to user projects as bundled template content?

"Changing template content — templates are the core product, changes affect all users" is ASK FIRST. Anything added to src/templates/ lands in every user's docs/templates/ on init and is upgrade-tracked by hash. This is the same underlying choice as D1 viewed from the boundary side, and it is mandatory for that reason.

Yes — ship it as a template

Recommended
  • Skills shipped to users cite a path that actually exists in their project
  • Matches the two existing occupants of src/templates/reference/
  • Upgrade machinery already handles nested reference keys
  • Adds permanent footprint to every user project
  • Imposes Joycraft's house voice on users who may not want it
  • Changing it later is a template change — this same boundary again
Blast radius
src/templates/reference/ src/bundled-files.ts TEMPLATES every user project on init/upgrade

No — repo-internal only

  • Zero user footprint; no template boundary crossed
  • Binds Joycraft's own authors, which is where output moments are written
  • Shipped skills would cite a dead path in user projects
  • Forces the pointer to be Joycraft-repo-only, splitting the contract
Blast radius
docs/reference/
D1 · WHERE THE DOC LIVES

Which home does the style doc take, and therefore whom does it bind?

Joycraft's own repo reads docs/reference/, but a user project receives bundled templates at docs/templates/reference/. A single pointer string cannot be correct in both places, so this choice determines whether the contract binds Joycraft's authors, its users, or both.

Ship it: src/templates/reference/output-style.md

Recommended
  • Path resolves in user projects, where the shipped skills run
  • Consistent with knowledge-lifecycle.md and spec-status-lifecycle.md
  • Upgrade-tracked by hash like every other template
  • Joycraft's own repo then reads it from docs/templates/, not docs/reference/ — mildly odd for self-hosting
  • User footprint (see B2)
Blast radius
src/templates/reference/ src/init.ts:197-203

Repo-internal: docs/reference/output-style.md

  • No user footprint; mirrors skill-authoring.md exactly
  • Binds the authors who actually write the output moments
  • Broken pointer in every user project — load-bearing failure
  • skill-authoring.md shows this home produces docs nothing cites
Blast radius
dead path for users

Both homes, split by audience

  • Each audience gets the rules it needs at a path that resolves
  • Authoring-time rules could extend the existing skill-authoring.md
  • Two homes for related rules — the exact ONE_HOME condition optimize flags
  • Doubles the drift surface
Blast radius
src/templates/reference/ docs/reference/skill-authoring.md
D2 · RULE-SET SHAPE

Short positively-framed rules, or a full anti-slop banned list?

The two research clusters contradict each other outright. The popular published artifacts (stop-slop ~14.6k stars, deslop, no-ai-slop) are long negative-constraint lists. Anthropic's first-party July 2026 guidance for Fable/Opus-4.8-era models is the opposite: fewer hard constraints, because "do not do this" rules over-fire in the 10% of cases where they are wrong. Nobody has tested banned-list skills against frontier Claude. This is the design's load-bearing anchor-50 claim and the reason the block rule fired.

Short positive rule set (~6–10 rules) with stated motivation

Recommended
  • Matches verified first-party guidance for the model generation Joycraft targets
  • Low always-loaded token cost; degrades gracefully when a rule doesn't fit
  • Stating motivation lets the model generalize instead of pattern-matching
  • The reconciliation is inference from docs, not measured — research Caveat 2 says so explicitly
  • May be too weak to change behavior at all; no eval either way
Blast radius
one reference doc all human-facing output

Full categorized banned-phrase list

  • The dominant published pattern with heavy real-world adoption
  • Concrete and mechanically checkable; precedent exists in the suite for a whole-file word ban
  • Directly contradicts Anthropic's guidance for recent models
  • Tell lists are self-described time-dated detectors needing re-profiling
  • Adoption is not efficacy — none ship a before/after eval
Blast radius
large always-loaded doc

Short positive rules + a small versioned tell list

  • Hedges the contradiction instead of betting on one side
  • Explicit versioning answers the research's open question on tell drift
  • More machinery, and the tell list still has no evidence behind it
  • Creates a recurring maintenance obligation at every model bump
Blast radius
reference doc + version metadata
D3 · TEST ENFORCEMENT

How much should a test enforce — the pointer, its placement, or the prose?

Prose quality has no mechanical oracle, and the suite has never asserted it. The existing content tests assert structural presence and ordering only. Going further re-introduces RF-KILL-2 (hard word-caps with silent cutting), already rejected. But a presence-only test proves wiring, not compliance.

Presence only

Recommended
  • Cheap; mirrors skill-handoff.test.ts substring assertions
  • No false positives; survives skill restructuring
  • Avoids the position-fragile windowing idiom entirely
  • A skill can cite the doc and still ignore it
  • Proves wiring, not behavior
Blast radius
tests/ (one new file)

Presence + ordering

  • Catches the pointer being buried where it won't be read at the right moment
  • The ordering assertion is already the most fragile idiom in the suite
  • Compounds the 1500-char window fragility this feature must avoid
Blast radius
windowed test regions

Presence + golden example in the doc

  • Research finding 7: concrete examples beat abstract instructions
  • Tests the doc's own usefulness, not just its existence
  • Tests the reference doc, not the skills that must obey it
Blast radius
tests/ + reference doc
Integrity

Assumptions asserted as fact

These are load-bearing claims this dossier rests on that were NOT posed to you as questions. Per RF-5, anything unchecked is labeled Unverified. This dossier is itself a persuasive artifact — including this line, and including which questions I chose to frame.

Verified

The build engine has no include/inject primitive. Read scripts/lib/skill-template.mjs: header at :5-8 enumerates exactly three primitives, module is pure/no-I/O at :1, and applyTemplate is the only export. Shared content must duplicate, abuse a 5th LOOKUP key, or extend the engine.

Verified

Bundled templates land at docs/templates/ in user projects. Read src/init.ts:197-203 — every TEMPLATES entry is written under docs/templates/ with ensureDir on the dirname, so nested reference/ keys already work.

Verified

The human-door budget is already full. grep "^entry:" src/skills/*.md returns 9 human, 11 agent, 2 situational; the 2026-07-21 decision-log row caps human doors at ≤9. A new user-invocable style skill would breach it.

Verified

Content tests read two different source-of-truth dirs. tests/skill-handoff.test.ts:7 reads generated src/claude-skills/; retrieval-pass-skill.test.ts:9-11 reads installed .claude/skills/. Both only see changes after the build step runs.

Unverified

A short positive rule set will actually change model output. Unchecked because no eval exists in either direction — the research says so in its own caveats. Verifying means running a before/after comparison on real Joycraft report output, which nobody in the cited literature has done.

Unverified

The reward-hacking result transfers to current Claude. Pan et al. 2024 measured GPT-3.5/GPT-4, not Claude. I used it to reject the rubric loop anyway. Verifying means replicating the writer-judge loop on a current model.

Unverified

The enumerated human-facing output moments are complete. Taken from the companion research doc's per-skill map, with approximate line numbers I did not re-walk skill by skill. Verifying means auditing all 22 skills directly.

Unverified

A one-line path pointer is sufficient to make an agent load and apply the doc. This is the mechanism the whole design rests on, assumed from the existing seven-skill pointer idiom. Nobody has checked whether agents actually follow those pointers at the output moment.

Unverified

My risk ranking is right. I pre-backlogged D4 (which skills get the pointer) and D5 (consolidating existing scattered directives) as lower blast radius. If you disagree, pull either back into this round — the ranking is my framing, not a fact.
