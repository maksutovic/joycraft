Questions for you

I1 → D10

Lock Pattern B for every gate question directive?

Recommend: approve — directives require ≥2 real options and route free-text via "<choice> because <reason>".

This traces to the 2026-07-20 decision-log row, not to D1–D9 or the brief, so decompose cannot self-approve it. It is the proven pattern (3/3 native-UI trials) and spec 2's free-text model/effort questions would otherwise risk the invalid single-option shape.

I2 → D11

Require a visible one-line confirmation on every defer-to-person?

Recommend: approve — who, which question, where recorded, every time.

The 2026-07-20 defer discovery showed agents execute file-mutating shortcuts silently unless the confirmation is in the ACs. Team deferral is exactly such a branch; without this a question can be assigned with no residue in chat.

I3 → D12

Persist the auto-open setting in docs/.joycraft/state.json?

Recommend: approve — reuse the existing version-state file, no new config surface.

The brief says "persisted on/off setting" but names no location. state.json already lives under docs/.joycraft and travels with the project; the alternative (a new settings file or CLAUDE.md line) adds a discovery surface for one boolean.

I4 → D13

Track revision as an integer in the HTML footer, incremented per re-render?

Recommend: approve — self-contained in the artifact, no new state file.

The brief says "revision banner" but names no mechanism. Reading the previous render's footer and incrementing keeps filenames stable and state local to the artifact; the alternative (revision counters in state.json) couples every gate render to shared state for a display-only number.
